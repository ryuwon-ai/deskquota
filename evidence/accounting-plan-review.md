# Plan Review - Chunk 1

**Status:** Issues Found

Reviewed the complete 191-line accounting-ablation plan against the accounting experiment proposal, benchmark specification, core quota design, and current benchmark source/method. This is a document/source review only: no product execution, builds, dependency changes, Git, network calls, or performance validation were performed.

**Issues:**

- **[Task 1, “paired 집계를 별도 모듈에서 검산한다”, lines 104–110] Use the actual timestamp schema and phase-specific duration.** The plan names `completed_monotonic_s`, but current outcomes contain `ended_s`; the existing cutoff is `ended_s <= run.start_monotonic_s + run.measurement_duration_s` (`product/scripts/benchmark.py:340`, `product/scripts/benchmark_http.py:238`). Specify this exact formula without a new alias/fallback. Require 300 seconds for the stated five-window quota experiment while handling the existing three-second smoke separately. Add an exact-boundary and just-after-boundary fixture, including rejection of a forged `within_measurement` value, so aggregate validation cannot accidentally count drain results or reject the smoke.

- **[Task 1, “명시적인 두 구성을 추가한다”, lines 72–77; Task 2, “부모가 독립적으로 첫 pair를 검산한다”, lines 162–167] Constrain normalization and retain independently inspectable configuration evidence.** “임시 listen/upstream port·path를 제외” can be read as excluding upstream URL paths, which would hide a different route or API base. Explicitly exclude only the allocated loopback port numbers and generated temporary filesystem paths. Preserve and compare upstream scheme/host/path/query, root IDs/endpoints/models, model limits, quota and all remaining settings. Specify a sanitized parsed configuration snapshot derived from the actual written TOML in each run, alongside its raw TOML hash; the current temporary TOML disappears and the current config metadata omits several fields, so a hash alone cannot support the promised later independent comparison. Include a changed upstream path or model-bound negative fixture.

- **[Task 1, Files/read-only boundary and correctness tests; Task 2, usage gate, lines 144–167] Define the usage evidence and expected exceptions before treating missing usage as a failed pilot.** The current HTTP client ignores usage frames, and `request_once` persists payload validity and timing but no received usage values (`product/scripts/benchmark_http.py:60–70, 223–227`). The mock records its computed actual cost, while gateway status exposes aggregate known/unknown counts and token totals (`product/src/metrics.rs:141–168`). These are different evidence classes. The plan currently promises raw usage recomputation without specifying which is validated or how, and its blanket missing-usage failure can reject expected metadata, pre-dispatch cancellations, rejected attempts, or disconnected streams. Specify concrete assertions and fields: either narrowly extend the HTTP helper to persist only validated numerical usage/validity for completed generation responses and compare them with fixture costs, or explicitly limit the gate to a defined aggregate-status reconciliation plus the identity-matched existing usage regressions. In either case, distinguish expected unknown/non-generation outcomes from missing usage on completed generation, account for cancellation/dispatch races without an invented fixed attempt count, and add a missing/altered completed-generation usage negative fixture appropriate to the chosen evidence method. Do not persist response/request bodies or credentials.

**Recommendations (advisory):**

- Give the new independent audit script a concrete CLI invocation, explicit first-pair/full-matrix mode or expected pair count, output path and nonzero-exit contract. Record the auditor source hash separately from the product measurement identity, and provide one forged-result rejection check before trusting the audit.
- The two-option scope, ordinary binary reuse, alternating seed order, unchanged production defaults, full-schedule pilot checkpoint, resume-before-spawn requirements, whole-denominator accounting, negative-result reporting and serialized SPEC/QUALITY gates are appropriate. No new scheduler/framework or broader production policy is needed.
- The requested matrix arithmetic is consistent: 5 seeds × 2 arms × 5 windows × 20 ingress = 1,000 ingress. The plan correctly avoids using the earlier reserved artifacts as concurrent controls and does not gate continuation on favorable performance.

**Disposition:** HOLD. Parent plan author should resolve the issues and request a document re-review; no implementation was performed.
